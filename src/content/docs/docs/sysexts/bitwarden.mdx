The Bitwarden extension adds the Bitwarden desktop password manager to a Frostyard desktop image. Use it when you want the Bitwarden app on a desktop image. Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard desktop bootc image: Snow, Snowfield, or Sundog, not Floe.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/bitwarden/`.
- Free space in `/var` for the download and the installed image.

The Bitwarden extension has no published test results on Frostyard images yet. Try it on a machine you can spare first.

## Enable Bitwarden

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=bitwarden
sudo updex features enable bitwarden --now
```

`bitwarden` appears as a component, with its feature disabled. The enable command downloads the image, checks its checksum and signature, links it, and refreshes the merge.

Check the merge and the files that the extension adds:

```bash
systemd-sysext status
command -v bitwarden
ls /usr/share/applications/bitwarden.desktop
```

`systemd-sysext status` lists `bitwarden`. `command -v` prints a path, and `ls` prints the launcher file.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the download worked but the merge did not. Run `sudo systemd-sysext refresh`, or reboot. Then run the checks above again.

## Use Bitwarden

Start Bitwarden from your applications, or run `bitwarden`. The extension ships no service and adds nothing to `/etc`.

## Update, roll back, and remove

See whether a newer image exists, then update:

```bash
updex features check --component=bitwarden
sudo updex features update --component=bitwarden
```

The update downloads the newest image and links it. A refresh replaces `/usr` under a running app, and a running app can fail. Close Bitwarden before you run `updex features update`, or update with `--no-refresh` and reboot. See [Manage system extensions](/docs/sysexts/manage/#update) for the check output and the update timer.

Roll back with `sudo updex features rollback bitwarden`. It takes effect at the next boot. See [Roll back](/docs/sysexts/manage/#roll-back).

Remove Bitwarden now:

```bash
sudo updex features disable bitwarden --now --force
```

Updex unmerges all extensions on the host, deletes the Bitwarden image, and merges the rest again. Your Bitwarden data stays in your home directory. Reboot when the command finishes. Without `--force`, Updex refuses while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package requests | The Bitwarden `.deb` (a pinned download), plus `libnotify4`, `libnss3`, `libxss1`, and `libxtst6` |
| Version | The image file name carries the `bitwarden` version, plus a `+rN` snosi revision when one is set |
| Command and launcher | `/usr/bin/bitwarden` and `/usr/share/applications/bitwarden.desktop`; the app lives in `/usr/lib/Bitwarden` |
| Services | None |
| Image file | `bitwarden_<version>_<os>_<arch>.raw.zst`; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/bitwarden/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

Each build checks that these paths are present: the Bitwarden binary, the sandbox helper, the `/usr/bin/bitwarden` link, the launcher, and the icon. A build that is missing one fails.
