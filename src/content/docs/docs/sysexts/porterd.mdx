The porterd extension adds `porterd`, the Porter assistant daemon, to a Frostyard bootc image. It runs as lodge's Porter app, with the app id `porter`. A server that runs the suite's services runs [Floe](/docs/images/floe/). Porter's own page is [Porter](/docs/apps/porter/). Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard bootc image built on Base.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/porterd/`.
- Free space in `/var` for the image.

porterd has no published test results on Frostyard images yet. Try it on a machine you can spare first.

You reach Porter in a browser through [lodge](/docs/sysexts/lodge/). Enable lodge first. Enabling porterd does not enable lodge: Updex features have no dependencies.

## Enable porterd

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=porterd
sudo updex features enable porterd --now
```

`porterd` appears as a component, with its feature disabled. The enable command
downloads the image, checks its checksum and signature, links it, and refreshes
the merge.

If `updex features list` does not show the feature, the image is older than the
extension. [Update the image](/docs/images/install-update/) first.

Start porterd:

Reboot. At boot the image merges the extensions, runs `systemd-sysusers` and
`systemd-tmpfiles --create`, reloads systemd, and `Upholds=` starts the units.

To start without a reboot:

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl start frostporter.socket frostporter.service
```

Without the first two commands, the socket fails on its group.

Check the units:

```bash
systemctl status frostporter.socket frostporter.service
```

`systemctl status` shows both units active.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the
download worked but the merge did not. Run `sudo systemd-sysext refresh`, or
reboot. Then run the checks above again.

## What runs

`frostporter.socket` and `frostporter.service` run on the host. The service is
upheld because its routines run without a client.

The drop-in `/usr/lib/systemd/system/multi-user.target.d/10-porterd.conf` has
`Upholds=` for both units, and the preset
`/usr/lib/systemd/system-preset/40-porterd.preset` enables both. Both start at
boot. If one stops, even with exit status 0, systemd starts it again. To stop it
for longer, remove the extension or mask the unit.

`extension-release.porterd` sets `EXTENSION_RELOAD_MANAGER=1`, so a merge or
refresh reloads systemd's unit files.

`frostporter.service` runs `/usr/bin/porterd` as the user `frostporter`, with
the groups `lodge-apps` and `lodge-agents`. It listens on no network, only on
Unix sockets. Its state is in `/var/lib/frostporter`, and each app's token is in
`/var/lib/frostporter/tokens`; set one with `porterd token set APP`.

The configuration belongs to you, and the extension ships no file in `/etc`:
`/etc/porter/porter.json`.

`frostporter.socket` listens on `/run/lodge/apps/porter.sock` as owner
`frostporter`, group `lodge`, mode `0660`.

The sysusers file `/usr/lib/sysusers.d/frostporter.conf` creates the user
`frostporter` and the group `lodge`, with `frostporter` in `lodge-apps` and
`lodge-agents`. The user is never in group `lodge`. Porter reaches the apps
through lodge's agent socket, so lodge's configuration must name it in
`agents`.

The command is `/usr/bin/porterd`, with no CLI. The lodge app files are in
`/usr/share/lodge/apps/porter/`.

## Update, roll back, and remove

Check for an update, then install it:

```bash
updex features check --component=porterd
sudo updex features update --component=porterd
```

The update takes effect at the next boot. Until then, the running daemon keeps
its old binary. See [Update](/docs/sysexts/manage/#update).

To switch without a reboot:

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl daemon-reload
sudo systemctl restart frostporter.socket frostporter.service
```

Roll back with `sudo updex features rollback porterd`. It takes effect at the
next boot. See [Roll back](/docs/sysexts/manage/#roll-back).

Remove porterd:

```bash
sudo updex features disable porterd --now --force
```

Updex unmerges all extensions on the host, deletes the image, and merges the
rest again. Reboot when the command finishes. Without `--force`, Updex refuses
while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package | `frostyard-porterd`, the `.deb` attached to the app's GitHub release, installed into the image with `dpkg`. The build checks the download against a pinned SHA-256 and checks its GitHub build-provenance attestation, and checks that its dependencies are met before it installs |
| Feature | `Porter (Porter assistant daemon and Lodge porter app)` |
| Command | `/usr/bin/porterd`, with no CLI |
| Service | `frostporter.service`, which runs `/usr/bin/porterd` as the user `frostporter` |
| Socket | `frostporter.socket` on `/run/lodge/apps/porter.sock`, owner `frostporter`, group `lodge`, mode `0660` |
| State | `/var/lib/frostporter`, with app tokens in `/var/lib/frostporter/tokens` |
| User and group | `frostporter`, group `lodge`, and `frostporter` in `lodge-apps` and `lodge-agents`, from `/usr/lib/sysusers.d/frostporter.conf` |
| Lodge app | `/usr/share/lodge/apps/porter/` |
| Activation | `/usr/lib/systemd/system/multi-user.target.d/10-porterd.conf` with `Upholds=`, and `/usr/lib/systemd/system-preset/40-porterd.preset` |
| Version | The image file name carries the `frostyard-porterd` package version, which is the app's release version |
| Image file | `porterd_<version>_<os>_<arch>.raw.zst`; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/porterd/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

Each build checks the command, the units, the sysusers file, the lodge app manifest and web page, and the preset, activation drop-in and extension-release files. A build that is missing one fails. Each build also checks that every upheld unit has no `Condition*=` line, or is a oneshot that stays active.
