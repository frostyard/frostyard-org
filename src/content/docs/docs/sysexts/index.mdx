A system extension adds software to the read-only `/usr` of a Frostyard bootc
image. Every image ships each extension switched off. You turn one on with
Updex.

## Find an extension

See what Updex found:

```bash
updex components
updex features list
```

Your image offers only the features it has files for. The catalog below lists
what the repository published at the last sync. If `updex features list` does
not show an extension, your image cannot enable it.

## Enable an extension

Enable one and download it now:

```bash
sudo updex features enable <name> --now
```

Replace `<name>` with the component name from the table. Check the merge:

```bash
systemd-sysext status
```

The output lists the extension you enabled. If `enable --now` exits with a
refresh error (`refresh_error` in JSON), the download worked but the merge did
not. Run `sudo systemd-sysext refresh`, or reboot.

## Check for updates and update

See what you can update to. This changes nothing:

```bash
updex features check
```

Install the newest versions:

```bash
sudo updex features update
```

To download and stage updates each day, turn on the Updex timer:

```bash
sudo updex daemon enable
```

The timer downloads and stages updates. It does not activate them. A staged
update starts after a refresh or a reboot.

## Stop updates or remove

Stop updates and keep the extension merged:

```bash
sudo updex features disable <name>
```

Remove the extension now:

```bash
sudo updex features disable <name> --now --force
```

Updex v2.0.4 and later refuse to remove a merged extension without `--force`.
Updex before v2.0.4 does not refuse: it removes the extension at once.
Removal unmerges all extensions on the host, then merges the rest again.
Reboot when the command finishes. If that refresh fails, the remaining
extensions stay unmerged until you run `sudo systemd-sysext refresh` or
reboot.
