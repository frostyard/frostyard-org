The readd extension adds `readd`, frostread's daemon, to a Frostyard bootc image. It runs as lodge's Read app, with the app id `read`. A server that runs the suite's services runs [Floe](/docs/images/floe/). frostread's own page is [frostread](/docs/apps/frostread/). Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard bootc image built on Base.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/readd/`.
- Free space in `/var` for the image.

readd has no published test results on Frostyard images yet. Try it on a machine you can spare first.

You reach Read in a browser through [lodge](/docs/sysexts/lodge/). Enable lodge first. The readd extension declares no dependency on lodge, so enabling readd does not enable lodge.

## Enable readd

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=readd
sudo updex features enable readd --now
```

`readd` appears as a component, with its feature disabled. The enable command
downloads the image, checks its checksum and signature, links it, and refreshes
the merge.

If `updex features list` does not show the feature, the image is older than the
extension. [Update the image](/docs/images/install-update/) first.

Start readd:

Reboot. At boot the image merges the extensions, runs `systemd-sysusers` and
`systemd-tmpfiles --create`, reloads systemd, and `Upholds=` starts the units.

To start without a reboot:

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl start frostread.socket frostread.service
```

Without the first two commands, the socket fails on its group.

Check the units and the feeds:

```bash
systemctl status frostread.socket frostread.service
sudo -u frostread readctl sources
```

`systemctl status` shows both units active. `readctl sources` lists the feeds.
`readctl` uses `/run/frostread/readctl.sock` by default.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the
download worked, but the activation did not. If the output says
`activation did not finish`, the extension is merged, but its users and groups
can be missing: reboot. Otherwise the merge failed: run
`sudo systemd-sysext refresh`, or reboot. Then run the checks above again.

## What runs

`frostread.socket` and `frostread.service` run on the host. The service is
upheld because its feed poller works without a client.

The drop-in `/usr/lib/systemd/system/multi-user.target.d/10-readd.conf` has
`Upholds=` for both units, and the preset
`/usr/lib/systemd/system-preset/40-readd.preset` enables both. Both start at
boot. If one stops, even with exit status 0, systemd starts it again. To stop it
for longer, remove the extension or mask the unit.

`extension-release.readd` sets `EXTENSION_RELOAD_MANAGER=1`, so a merge or
refresh reloads systemd's unit files.

`frostread.service` runs `/usr/bin/readd --socket /run/frostread/readctl.sock`
as the user `frostread`, with the groups `lodge-apps` and `lodge-agents`. Its
state is in `/var/lib/frostread`. readd reaches the public web itself, to fetch
feeds.

The configuration belongs to you, and the extension ships no file in `/etc`:
`/etc/frostread/frostread.json`.

`frostread.socket` listens on `/run/lodge/apps/read.sock` as owner `frostread`,
group `lodge`, mode `0660`.

The sysusers file `/usr/lib/sysusers.d/frostread.conf` creates the user
`frostread` and the group `lodge`, with `frostread` in `lodge-apps` and
`lodge-agents`. The user is never in group `lodge`. Save-as-note needs lodge's
configuration to name `frostread` in `agents`.

The commands are `/usr/bin/readd` and `/usr/bin/readctl`. The lodge app files
are in `/usr/share/lodge/apps/read/`.

## Update, roll back, and remove

Back up frostread's state before you update. readd migrates its database when
it starts, and an older readd refuses a database with a newer schema. A
rollback does not undo a migration.

Stop frostread for the backup. Systemd starts upheld units again, so mask them
while you copy. While frostread is stopped, the Read tab does not work, the
poller does not run, and lodge shows the app as down. The state holds the
notes token, so keep the archive root-only:

```bash
sudo systemctl mask --now frostread.socket frostread.service
sudo sh -c 'umask 077; tar -czpf /root/frostread-state-$(date -u +%Y%m%dT%H%MZ).tar.gz /var/lib/frostread'
sudo systemctl unmask frostread.socket frostread.service
sudo systemctl start frostread.socket frostread.service
```

`tar` exits 0, and `systemctl status frostread.socket frostread.service` shows
both units active again.

Check for an update, then install it:

```bash
updex features check --component=readd
sudo updex features update --component=readd
```

By default, the update merges the new files at once, and systemd reloads its
unit files. Updex v2.1.3 and later also create new users, groups, and
directories at once. An older Updex leaves them for the next boot. The running
readd keeps its old binary until it restarts. A reboot applies everything.

The new files wait for the next boot when you pass `--no-refresh`, when the
automatic update timer installs the update, or when the output says
`refresh skipped`: Updex skips the refresh when it cannot refresh safely. Then
reboot. See [Update](/docs/sysexts/manage/#update).

With an Updex older than v2.1.3, run these commands first. `updex --version`
shows your version.

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl daemon-reload
```

To run the new version now, restart frostread, then let lodge read the new
manifest:

```bash
sudo systemctl restart frostread.socket frostread.service
sudo lodgectl reload
```

Check the version that runs:

```bash
sudo -u frostread readctl status
sudo lodgectl apps
```

`readctl status` prints `readd <version>` with the new version. `lodgectl apps`
lists `read` up, with the new version.

Roll back to the previous version:

```bash
sudo updex features rollback readd
```

The rollback takes effect at the next boot. To apply it now, add `--now`, then
restart frostread as above. See [Roll back](/docs/sysexts/manage/#roll-back).

When the older version runs, read the journal:

```bash
journalctl -u frostread.service -n 50
```

If it shows `database schema N is newer than this readd`, the newer readd
migrated the database. Restore the state from your backup. Replace `ARCHIVE`
with the path of the archive:

```bash
sudo systemctl mask --now frostread.socket frostread.service
sudo rm -rf /var/lib/frostread
sudo tar -xzpf ARCHIVE -C / var/lib/frostread
sudo systemctl unmask frostread.socket frostread.service
sudo systemctl start frostread.socket frostread.service
```

The restore loses what changed after the backup: new items, reads, and saves.

Remove readd:

```bash
sudo updex features disable readd --now --force
```

Updex unmerges all extensions on the host, deletes the image, and merges the
rest again. Reboot when the command finishes. Without `--force`, Updex refuses
while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package | `frostyard-readd`, the `.deb` attached to the app's GitHub release, installed into the image with `dpkg`. The build checks the download against a pinned SHA-256, and checks that its dependencies are met before it installs. Its GitHub build-provenance attestation is checked when the pin is set and in every CI build, before the image is built |
| Feature | `Read (frostread feed reader daemon and Lodge read app)` |
| Commands | `/usr/bin/readd` and `/usr/bin/readctl` |
| Service | `frostread.service`, which runs `/usr/bin/readd --socket /run/frostread/readctl.sock` as the user `frostread` |
| Socket | `frostread.socket` on `/run/lodge/apps/read.sock`, owner `frostread`, group `lodge`, mode `0660` |
| Private socket | `/run/frostread/readctl.sock`, for `readctl` |
| State | `/var/lib/frostread` |
| User and group | `frostread`, group `lodge`, and `frostread` in `lodge-apps` and `lodge-agents`, from `/usr/lib/sysusers.d/frostread.conf` |
| Lodge app | `/usr/share/lodge/apps/read/` |
| Activation | `/usr/lib/systemd/system/multi-user.target.d/10-readd.conf` with `Upholds=`, and `/usr/lib/systemd/system-preset/40-readd.preset` |
| Version | The image file name carries the `frostyard-readd` package version, which is the app's release version |
| Image file | `readd_<version>_13_x86-64.raw.zst`, where `13` is the OS version ID; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/readd/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

<ExtensionSnapshot name="readd" />

Each build checks the commands, the units, the sysusers file, the lodge app manifest and web page, and the preset, activation drop-in and extension-release files. A build that is missing one fails. Each build also checks that every upheld unit has no `Condition*=` line, or is a oneshot that stays active.
