Incus is an opt-in system extension for Frostyard bootc images. It supplies the
Incus daemon, CLI, web UI, container runtime, virtual-machine support, and the
bundled QEMU runtime. The Base image registers the component and ships it
disabled. Enabling it is an operator choice, not part of the default desktop or
server payload.

## Purpose and host prerequisites

Use this extension when a host needs Incus containers or virtual machines.
Incus is a system service: it creates and runs workloads, manages storage and
networks, and exposes a local socket. The extension supplies that service under
`/usr`; it does not supply a host package manager or a supported in-place
replacement for an existing distribution installation.

Prerequisites:

- A Frostyard bootc image built on the shared Base, with `systemd-sysext` and
  the Base `frostyard-updex` binary.
- Root access for enable, update, and removal. The read-only checks below are
  shown without `sudo`.
- Network access to `https://repository.frostyard.org/ext/incus/`.
- Free space in `/var` for the extension image and for the workload storage you
  plan to create.
- A host that supports the virtualization features your workloads need. The
  extension carries OVMF and a QEMU runtime, but firmware settings and CPU
  virtualization remain host responsibilities.
- A backup or export of existing containers, virtual machines, and storage
  pools before you change the extension.

The pinned sources do not contain a per-product live test record for this
extension. Existing design text records a past Incus failure on one product and
the rebuild that addressed it; that is a design record, not a current test
result for every product.

The transfer sets `CurrentSymlink=incus.raw`, but Updex removes the legacy
`/var/lib/extensions.d/incus.raw` during installation. The live link is
`/var/lib/extensions/incus.raw`, and it points to the selected image in
`/var/lib/extensions.d/`. See
[`updex/install.go`](https://github.com/frostyard/updex/blob/a76548350995ecbe80371e57a24d7d844ceb408d/updex/install.go)
and
[`sysext/manager.go`](https://github.com/frostyard/updex/blob/a76548350995ecbe80371e57a24d7d844ceb408d/sysext/manager.go).

The checked catalog snapshot is generated and its version can change. The
pinned build configuration sets `SYSEXT_REVISION=3`; a build from this source
carries revision 3. The snapshot and the build configuration are separate
facts. Do not read the snapshot as the current published revision or as the
newest available version.

The executable APT source is
[`frostyard.sources`](https://github.com/frostyard/snosi/blob/5b610e3db1017e0ccc9a5dabc10b841e80c1d2e5/mkosi.sandbox/etc/apt/sources.list.d/frostyard.sources):
`https://repository.frostyard.org/debian/`. It agrees with the design document:
the shipped `incus` is a Frostyard rebuild of Zabbly's deb and bundles QEMU,
OVMF, swtpm, and virtiofsd under `/usr/incus`. The `mkosi.conf` comment that
says Debian Trixie is stale.

The package row lists build requests. It does not promise that every request
ships in the delta. Base already ships `qemu-system-x86`, `qemu-utils`, and
`ovmf` in
[`mkosi.images/base/mkosi.conf`](https://github.com/frostyard/snosi/blob/5b610e3db1017e0ccc9a5dabc10b841e80c1d2e5/mkosi.images/base/mkosi.conf),
and a sysext delta omits packages that Base provides. The Incus delta therefore
does not carry Debian `ovmf` or `qemu-utils`. It still carries unused
`qemu-kvm`, `qemu-system-gui`, `qemu-system-modules-spice`, and `ipxe-qemu`
pending #1014. These Debian leftovers are separate from the bundled
`/usr/incus` runtime.

The bundled runtime matters operationally. `incusd` prepends `/usr/incus/bin`
to `PATH`, so it probes `/usr/incus/bin/qemu-system-x86_64`, not Debian's
`/usr/bin/qemu-system-x86_64`. The extension's required-path list pins the
GTK3 and media libraries that the bundled binary needs. A Base shrink can
invalidate an older delta; the design document records exactly that failure
mode and the rebuild that restored the libraries.

The transfer selects the OS version with `%w` and the architecture with `%a`.
The checked catalog snapshot lists a version but no architecture matrix, so do
not infer support for an architecture from the snapshot alone. The delta is
built against the Base in this checkout. A Base with a different composition,
or a later Base shrink, can invalidate the published delta even when the OS and
architecture match. The required-path check protects the build, not a host with
a different Base.

## Choose Incus

Incus is the system container and virtual-machine manager. It is a separate
choice from Docker, which supplies a Docker Engine and CLI for application
containers. The two extensions own different daemons and sockets, but the
pinned sources do not define a supported joint workload contract. Do not run
both as a substitute for testing your specific combination.

The extension is built against Base, not against a desktop-only build base, so
its delta carries the graphical libraries that Floe lacks. That makes it usable
on a server image and on a desktop, but a desktop already supplies some of the
same libraries. The required-path list exists to keep the server case complete.

## Enable

List the component and inspect its feature:

```bash
updex components
updex features list --component=incus
```

Enable it and download it now:

```bash
sudo updex features enable incus --now
```

The enable drop-in is written to
`/etc/sysupdate.incus.d/incus.feature.d/00-updex.conf`. Without `--now`, the
feature is enabled for future updates but no image is downloaded. With
`--now`, Updex downloads the image, verifies the checksum and detached
signature, creates the sysext link, and refreshes the merged extensions. The
transfer sets `Verify=true`; a missing or invalid signature fails the operation
and Updex does not fall back to an unsigned image.

Check the merge and the services:

```bash
systemd-sysext status
systemctl status incus.socket incus-startup.service incus-sysext-setup.service
```

`incus.service` is socket-activated. The socket and the setup service are the
important early checks. The setup service adds a subordinate UID/GID range for
root with `usermod`, so user namespaces work without a manual first-boot step.
It is ordered after sysusers and tmpfiles and before the Incus sockets and
startup service.

`--now` refreshes the overlay. It does not prove that setup completed. The Base
image's [`reload-sysext.service`](https://github.com/frostyard/snosi/blob/5b610e3db1017e0ccc9a5dabc10b841e80c1d2e5/mkosi.images/base/mkosi.extra/usr/lib/systemd/system/reload-sysext.service)
runs `systemd-sysusers`, `systemd-tmpfiles --create --graceful`, and
`systemctl daemon-reload` after `systemd-sysext.service` at boot. If the
`dnsmasq` or `rdma` identities, the factory configuration, or
`incus-sysext-setup.service` are missing after an interactive merge, reboot and
check again. A successful merge does not guarantee that the setup service ran
or that every service started.

If `enable --now` reports a refresh failure (`refresh_error` in JSON), Updex
reports the completed steps, but the final refresh failed. Treat the merge
state as unproven. Run `sudo systemd-sysext refresh` or reboot, then check
`systemd-sysext status` and `systemctl status incus.socket incus-sysext-setup.service`.
Do not treat the non-zero exit as a successful activation.

## Updates and removal

Check for an update without changing state:

```bash
updex features check --component=incus
```

`features check` iterates the enabled features in scope. For each enabled
feature, it fetches and verifies each transfer's manifest. A feature that is not
enabled gets no row; no row is not an up-to-date result. If a manifest cannot be
fetched or verified, the feature is reported as `UPDATE=error`, the other
enabled features are still reported, and the command exits non-zero. An errored
row is not an up-to-date result.

Install the newest available version:

```bash
sudo updex features update --component=incus
```

`update` downloads, verifies, installs, relinks, vacuums older versions by
default, and refreshes the merged extensions. `--no-vacuum` keeps older
versions. `sudo updex --dry-run features update --component=incus` previews the
selection and removals without writing to disk.

An interactive update refreshes `/usr` while the host is running. Stop or
migrate running containers and virtual machines before the refresh if a daemon
restart would interrupt them. A sysext only supplies `/usr`, so Incus workload
data is outside the extension's update and removal paths. The pinned sources do
not name the Incus state directory; inspect your storage pool configuration and
back up or export the workloads before removal.

Stop future updates without removing the current image:

```bash
sudo updex features disable incus
```

`disable` without `--now` writes only `Enabled=false`. The
`/var/lib/extensions/incus.raw` link stays, so the current image stays merged
and active now and at every boot. Incus keeps running; the daemon is not
stopped. `features update` and the timer skip the disabled feature.

:::danger[Removal acts immediately]
`sudo updex features disable incus --now` takes effect at once, also when the
extension is merged. Current Updex does not detect a merged image on snosi
hosts, so the `--force` guard does not fire
([Updex #444](https://github.com/frostyard/updex/issues/444)). It unmerges all
extensions on the host, removes the Incus image, and refreshes. If the final
refresh fails, the remaining extensions stay unmerged. Running containers and
virtual machines can stop immediately. Stop or migrate host-wide workloads
before you run it. If Updex refuses with "Extension ... is active", add
`--force`. Do not rely on that refusal as a safety check.
:::

To remove the installed image now:

```bash
sudo updex features disable incus --now
```

Removal deletes the staged image and the sysext link. The daemon, CLI, web UI,
and units disappear after the refresh or reboot. Containers, virtual machines,
storage pools, and other data under `/var` are not part of the extension; they
remain and must be managed separately. Do not assume that re-enabling the
extension restores a running workload or a missing storage pool. If the final
refresh fails after `disable --now`, all remaining extensions stay unmerged
until a later refresh or reboot.

For unattended staging:

```bash
sudo updex daemon enable
updex daemon status
sudo updex daemon disable
```

The Updex timer stages updates daily with `--no-refresh`; it never refreshes the
running system. Activation happens at a later refresh or reboot. This is
different from an interactive update, and an active timer does not mean the
newest version is running.

## Special cases and containers

Incus runs privileged system workloads. The extension creates the `dnsmasq`
user, the `rdma` group, the runtime directories, and the alternatives links
that the packaged tools expect. It also captures only the `/etc` paths named by
its tmpfiles rules, so the published image does not carry the build host's
entire `/etc`.

The factory configuration is copied into `/etc` only when the target is absent.
Local edits to `/etc/default/incus`, the libvirt configuration, or the QEMU
network helpers persist. The factory source remains under
`/usr/share/factory/etc`.

The extension ships `virt-viewer` and the QEMU display modules for graphical
console access. The bundled QEMU is the runtime that Incus probes. Do not
replace it with a host package or assume that a host `qemu-system-x86_64`
change affects Incus.

## Troubleshooting

| Symptom | Source-backed check | Safe next action |
| --- | --- | --- |
| `incus launch --vm` reports that virtual machines are unsupported | `incus info` and look for the QEMU driver, for example `driver: lxc \| qemu` | If only `lxc` is present, the bundled QEMU runtime is not loading. Check the merged extension and its libraries. |
| The bundled QEMU fails with a missing shared library | `LD_LIBRARY_PATH=/usr/incus/lib/ ldd /usr/incus/bin/qemu-system-x86_64` | The extension delta is incomplete for this Base. Publish or install a corrected extension; do not patch the host's `/usr` by hand. |
| The setup service did not run | `systemctl status incus-sysext-setup.service` and the journal | Check that `/run/incus-sysext-setup.done` is absent before the run. The unit is a oneshot guarded by that marker. |
| The Incus socket is inactive | `systemctl status incus.socket` and `systemd-sysext status` | Confirm the extension is merged and the preset was applied. Refresh or reboot after staging. |
| `enable --now` exits non-zero after downloading | The command reports a refresh failure (`refresh_error` in JSON) | Run `sudo systemd-sysext refresh` or reboot, then check `systemd-sysext status`. |
| A manifest or signature check fails | `updex features check --component=incus` | Keep verification enabled and check the published manifest and network path. |
| Containers or VMs stop during an update | The journal shows the daemon restart and the `/usr` refresh | Drain or migrate workloads before an interactive update. Back up storage first. |

The extension does not provide a supported host `apt` repair path. If a required
path is missing, use the build-time required-path check and publish a corrected
extension.
