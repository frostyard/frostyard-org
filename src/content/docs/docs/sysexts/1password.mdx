The 1Password desktop extension adds the 1Password app to a Frostyard desktop image, with its browser-support helper and the `op-ssh-sign` Git signing helper. Use it when you want 1Password on a desktop image. Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard desktop bootc image: Snow, Snowfield, or Sundog, not Floe.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/1password/`.
- Free space in `/var` for the download and the installed image.

The 1Password desktop extension has no published test results on Frostyard images yet. Try it on a machine you can spare first.

## Enable 1Password desktop

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=1password
sudo updex features enable 1password --now
```

`1password` appears as a component, with its feature disabled. The enable command downloads the image, checks its checksum and signature, links it, and refreshes the merge.

Check the merge and the files that the extension adds:

```bash
systemd-sysext status
command -v 1password op-ssh-sign
ls /usr/share/applications/1password.desktop
```

`systemd-sysext status` lists `1password`. Each name prints a path, and `ls` prints the launcher file.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the download worked but the merge did not. Run `sudo systemd-sysext refresh`, or reboot. Then run the checks above again.

## Use 1Password desktop

Start 1Password from your applications, or run `1password`.

The extension adds two groups at boot: `onepassword` (GID 1936) and `onepassword-mcp` (GID 1938). The browser-support helper and the `1password-mcp` helper run with these groups.

The polkit policy that the extension ships names the `onepassword` group as its owner. Members of that group get the system authentication integration for the 1Password command line and the SSH agent.

To join the group, run:

```bash
sudo usermod -aG onepassword "$USER"
```

Then sign out and sign in again. `id` lists `onepassword` after you sign in.

The extension copies `custom_allowed_browsers` into `/etc/1password/` from `/usr/share/factory/etc/1password` at boot. Edit the copy in `/etc` to change which browsers 1Password allows.

## Update, roll back, and remove

See whether a newer image exists, then update:

```bash
updex features check --component=1password
sudo updex features update --component=1password
```

The update downloads the newest image and links it. A refresh replaces `/usr` under a running app, and a running app can fail. Close 1Password desktop before you run `updex features update`, or update with `--no-refresh` and reboot. See [Manage system extensions](/docs/sysexts/manage/#update) for the check output and the update timer.

Roll back with `sudo updex features rollback 1password`. It takes effect at the next boot. See [Roll back](/docs/sysexts/manage/#roll-back).

Remove 1Password desktop now:

```bash
sudo updex features disable 1password --now --force
```

Updex unmerges all extensions on the host, deletes the 1Password desktop image, and merges the rest again. Your 1Password data stays in your home directory. Reboot when the command finishes. Without `--force`, Updex refuses while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package requests | The 1Password `.deb` (a pinned download), plus `curl`, `gnupg2`, `libasound2`, `libatk-bridge2.0-0`, `libatk1.0-0`, `libcurl4`, `libdrm2`, `libgbm1`, `libgtk-3-0`, `libnotify4`, `libnss3`, `libxcb-shape0`, `libxcb-xfixes0`, `libxshmfence1`, `libudev1`, and `xdg-utils` |
| Version | The image file name carries the `1password` version, plus a `+rN` snosi revision when one is set |
| Command and launcher | `/usr/bin/1password`, `/usr/bin/op-ssh-sign`, and `/usr/share/applications/1password.desktop` |
| Groups | `onepassword` (GID 1936) and `onepassword-mcp` (GID 1938), created at boot after the merge |
| Files in `/etc` | `/etc/1password/custom_allowed_browsers`, copied at boot from `/usr/share/factory/etc/1password` |
| Polkit | A system-authentication policy that names the `onepassword` group as owner |
| Services | None |
| Image file | `1password_<version>_<os>_<arch>.raw.zst`; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/1password/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

<ExtensionSnapshot name="1password" />

Each build checks that these paths are present: the 1Password binary, the sandbox helper, the browser-support helper, the two `/usr/bin` links, the launcher and icon, the sysusers and tmpfiles files, the factory `custom_allowed_browsers` file, and the polkit policy. A build that is missing one fails.
