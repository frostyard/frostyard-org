The Claude Desktop extension adds the Claude desktop app to a Frostyard desktop image. Use it when you want the app on a desktop image. Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard desktop bootc image: Snow, Snowfield, or Sundog, not Floe.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/claude-desktop/`.
- Free space in `/var` for the download and the installed image.

The Claude Desktop extension has no published test results on Frostyard images yet. Try it on a machine you can spare first.

## Enable Claude Desktop

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=claude-desktop
sudo updex features enable claude-desktop --now
```

`claude-desktop` appears as a component, with its feature disabled. The enable command downloads the image, checks its checksum and signature, links it, and refreshes the merge.

Check the merge and the files that the extension adds:

```bash
systemd-sysext status
command -v claude-desktop
ls /usr/share/applications/com.anthropic.Claude.desktop
```

`systemd-sysext status` lists `claude-desktop`. `command -v` prints a path, and `ls` prints the launcher file.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the download worked but the merge did not. Run `sudo systemd-sysext refresh`, or reboot. Then run the checks above again.

## Use Claude Desktop

Start Claude Desktop from your applications, or run `claude-desktop`. The extension ships no service and adds nothing to `/etc`.

## Update, roll back, and remove

See whether a newer image exists, then update:

```bash
updex features check --component=claude-desktop
sudo updex features update --component=claude-desktop
```

The update downloads the newest image and links it. A refresh replaces `/usr` under a running app, and a running app can fail. Close Claude Desktop before you run `updex features update`, or update with `--no-refresh` and reboot. See [Manage system extensions](/docs/sysexts/manage/#update) for the check output and the update timer.

Roll back with `sudo updex features rollback claude-desktop`. It takes effect at the next boot. See [Roll back](/docs/sysexts/manage/#roll-back).

Remove Claude Desktop now:

```bash
sudo updex features disable claude-desktop --now --force
```

Updex unmerges all extensions on the host, deletes the Claude Desktop image, and merges the rest again. Your Claude Desktop data stays in your home directory. Reboot when the command finishes. Without `--force`, Updex refuses while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package requests | `claude-desktop` (from the Anthropic APT repository that the build uses) and `libglib2.0-bin` |
| Version | The image file name carries the `claude-desktop` version, plus a `+rN` snosi revision when one is set |
| Command and launcher | `/usr/bin/claude-desktop` and `/usr/share/applications/com.anthropic.Claude.desktop` |
| Services | None |
| Image file | `claude-desktop_<version>_<os>_<arch>.raw.zst`; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/claude-desktop/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

Each build checks that these paths are present: the app binary, the sandbox helper, the `/usr/bin/claude-desktop` link, the launcher, and the icon. A build that is missing one fails.
