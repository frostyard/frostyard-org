The lodge extension adds lodge, the tailnet web shell for Frostyard's apps, to a Frostyard bootc image. It serves Notes, Mail, Read, and Porter from one address on your tailnet. Its own page is [lodge](/docs/apps/lodge/). A server that runs the suite's services runs [Floe](/docs/images/floe/). Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard bootc image built on Base.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/lodge/`.
- Free space in `/var` for the image.

lodge has no published test results on Frostyard images yet. Try it on a machine you can spare first.

## Enable lodge

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=lodge
sudo updex features enable lodge --now
```

`lodge` appears as a component, with its feature disabled. The enable command
downloads the image, checks its checksum and signature, links it, and refreshes
the merge.

If `updex features list` does not show the feature, the image is older than the
extension. [Update the image](/docs/images/install-update/) first.

Before the first start, make the configuration directory:

```bash
sudo install -d -m 0755 /etc/lodge
```

Put a tagged, pre-approved Tailscale key as `TS_AUTHKEY` in
`/etc/lodge/lodge.env`, owned by root, mode `0600`, before the first start.
Without one, `sudo lodgectl status` shows each node's login URL. Remove
`TS_AUTHKEY` from the file after the first start.

Start lodge:

Reboot. At boot the image merges the extensions, runs `systemd-sysusers` and
`systemd-tmpfiles --create`, reloads systemd, and `Upholds=` starts the unit.

To start without a reboot:

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl start lodge.service
```

Check the merge and the unit:

```bash
systemd-sysext status
systemctl status lodge.service
sudo lodgectl status
```

`systemd-sysext status` lists `lodge`, `systemctl status` shows the unit active,
and `lodgectl status` shows lodge's nodes, apps, sessions, providers, and agent
socket.

Allow people and devices:

```bash
sudo lodgectl allow login <login>
sudo lodgectl allow node <node>
```

To add agents and inference providers, copy
`/usr/share/lodge/config.example.json` to `/etc/lodge/config.json`, edit it,
then run `sudo lodgectl reload`.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the
download worked but the merge did not. Run `sudo systemd-sysext refresh`, or
reboot. Then run the checks above again.

## What runs

`lodge.service` runs on the host, and it is the only unit. There is no socket
unit.

The drop-in `/usr/lib/systemd/system/multi-user.target.d/10-lodge.conf` has
`Upholds=` for the unit, and the preset
`/usr/lib/systemd/system-preset/40-lodge.preset` enables it. It starts at boot.
If it stops, even with exit status 0, systemd starts it again. To stop it for
longer, remove the extension or mask the unit.

`extension-release.lodge` sets `EXTENSION_RELOAD_MANAGER=1`, so a merge or
refresh reloads systemd's unit files.

`lodge.service` runs `/usr/bin/lodge` as the user `lodge`, with its state in
`/var/lib/lodge`.

The sysusers file `/usr/lib/sysusers.d/lodge.conf` creates the user and group
`lodge`, and the groups `lodge-apps` and `lodge-agents`, with `lodge` in both.
The tmpfiles file `/usr/lib/tmpfiles.d/lodge.conf` creates `/run/lodge`, owned
by `lodge`, and `/run/lodge/apps`, owned by root, and `/var/lib/lodge`, owned
by `lodge`, mode `0700`. `lodge.service` has no `RuntimeDirectory=`, so
stopping lodge does not remove the apps' sockets.

The configuration belongs to you, and the extension ships no file in `/etc`:
`/etc/lodge/config.json` and `/etc/lodge/lodge.env`. lodge starts without them.
A missing `config.json` means no agents and no providers.

The web shell is `/usr/share/lodge/shell/`, and the commands are
`/usr/bin/lodge` and `/usr/bin/lodgectl`. The extension ships no app: each app
extension adds its own under `/usr/share/lodge/apps/`.

## Update, roll back, and remove

Check for an update, then install it:

```bash
updex features check --component=lodge
sudo updex features update --component=lodge
```

The update merges the new files at once, and systemd reloads its unit files.
The running daemon keeps its old binary until it restarts. New users, groups,
and directories wait for the next boot. A reboot applies everything. Only
`--no-refresh` and the automatic update timer leave the whole update for the
next boot. See [Update](/docs/sysexts/manage/#update).

To switch now, without a reboot:

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl daemon-reload
sudo systemctl restart lodge.service
```

Roll back with `sudo updex features rollback lodge`. It takes effect at the next
boot. See [Roll back](/docs/sysexts/manage/#roll-back).

Remove lodge:

```bash
sudo updex features disable lodge --now --force
```

Updex unmerges all extensions on the host, deletes the image, and merges the
rest again. Reboot when the command finishes. Without `--force`, Updex refuses
while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package | `frostyard-lodge`, the `.deb` attached to the app's GitHub release, installed into the image with `dpkg`. The build checks the download against a pinned SHA-256, and checks that its dependencies are met before it installs. Its GitHub build-provenance attestation is checked when the pin is set and in every CI build, before the image is built |
| Feature | `Lodge (tailnet web shell for Frostyard's first-party apps)` |
| Commands | `/usr/bin/lodge` and `/usr/bin/lodgectl` |
| Service | `lodge.service`, which runs `/usr/bin/lodge` as the user `lodge` |
| State | `/var/lib/lodge`, mode `0700` |
| User and group | `lodge`, groups `lodge-apps` and `lodge-agents`, with `lodge` in both, from `/usr/lib/sysusers.d/lodge.conf` |
| Runtime directories | `/usr/lib/tmpfiles.d/lodge.conf`: `/run/lodge`, owned by `lodge`, and `/run/lodge/apps`, owned by root |
| Web shell | `/usr/share/lodge/shell/` |
| Example configuration | `/usr/share/lodge/config.example.json` |
| Activation | `/usr/lib/systemd/system/multi-user.target.d/10-lodge.conf` with `Upholds=`, and `/usr/lib/systemd/system-preset/40-lodge.preset` |
| Version | The image file name carries the `frostyard-lodge` package version, which is the app's release version |
| Image file | `lodge_<version>_13_x86-64.raw.zst`, where `13` is the OS version ID; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/lodge/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

Each build checks the commands, the unit, the sysusers and tmpfiles files, the web shell's `index.html`, the example configuration, and the preset, activation drop-in and extension-release files. A build that is missing one fails. Each build also checks that every upheld unit has no `Condition*=` line, or is a oneshot that stays active.
