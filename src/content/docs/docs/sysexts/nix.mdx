The Nix extension adds the Nix package manager and its multi-user daemon to a
Frostyard bootc image. Use it when you want Nix packages and profiles next to
the software the image ships. Every image carries the extension's definition,
switched off. The extension itself is not in the image: Updex turns it on and
downloads it.

## Before you start

You need:

- A Frostyard bootc image. Every image built on Base has `systemd-sysext` and
  `frostyard-updex`.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/nix/`, and to the
  sources your Nix expressions fetch.
- Free space in `/var` for the image and for the Nix store and profiles. The
  store grows with each package and profile you add.
- The user names you will add to the `nix-users` group.

Nix has no published test results on Frostyard images yet. Try it on a machine you can spare first.

## Enable Nix

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=nix
sudo updex features enable nix --now
```

`nix` appears as a component, with its feature disabled. The enable command
downloads the image, checks its checksum and signature, links it, and refreshes
the merge.

Check that the image is merged, the mount is up, and the daemon runs:

```bash
systemd-sysext status
systemctl status nix.mount nix-daemon.service
```

`systemd-sysext status` lists `nix`. `nix.mount` puts `/var/lib/nix` at `/nix`,
and the daemon is bound to that mount, so it stops when the mount fails.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the
download worked but the merge did not. Run `sudo systemd-sysext refresh`, or
reboot. Then run the two checks above again.

## Use Nix

Client access is opt-in. The extension recreates Debian's `nix-users` group and
adds nobody to it. Add your account:

```bash
sudo usermod -aG nix-users USER
```

Replace `USER` with your user name. Log out and in again: the new session has
the group. This grants access to the daemon socket. It does not grant Nix
`trusted-users` privileges.

Check the command and the store:

```bash
command -v nix
ls /nix/store
```

Every user can read the store. Only the `nix-users` group can reach the daemon
socket, and the daemon does the writes.

Multi-user builds run as `nixbld1` to `nixbld10`, all members of the `nixbld`
group, at the UIDs and GIDs that the official Nix installer uses. Profiles and
garbage-collection roots live under `/var/lib/nix/profiles` and
`/var/lib/nix/gcroots`, which you also see under the `/nix` mount. Both
directories are world-writable, so any user can create a profile or register a
root.

The Nix configuration lives in `/etc/nix`. The extension keeps a default copy
in `/usr/share/factory/etc` and copies it into `/etc` at boot when `/etc/nix`
is missing. Edit the files in `/etc/nix`; your edits survive reboots and
updates. The copy happens only once, so a later update with new Nix defaults
does not change an existing `/etc/nix`.

## Update and remove

An update refreshes the merged `/usr` while the daemon runs. Let running
builds finish before you update by hand. Your store, profiles, and roots in
`/var/lib/nix` stay.

Remove Nix now:

```bash
sudo updex features disable nix --now --force
```

Updex unmerges all extensions on the host, deletes the Nix image, and merges
the rest again. The mount unit and the daemon go. `/var/lib/nix` stays, with
every store path and profile you built. Reboot when the command finishes.
Without `--force`, Updex refuses while the image is merged.

### Roll back

Updex v2.0.6 has no rollback command. To keep the version you run, stop
updates with `sudo updex features disable nix`. To remove the extension, use
the command above. `/var/lib/nix` stays either way. A rollback command is planned. See
[Roll back](/docs/sysexts/manage/#roll-back).

See [Manage system extensions](/docs/sysexts/manage/) for the update check, the
timer, and plain `disable`.

## Troubleshooting

| Symptom | Check | Fix |
| --- | --- | --- |
| A Nix command fails with a permission error | `id -nG USER` and `systemctl status nix-daemon.service` | Add the user to `nix-users` with `sudo usermod -aG nix-users USER`, then start a new login session. |
| `nix-users` is missing | `getent group nix-users` | The group comes from `usr/lib/sysusers.d/nix.conf`, and the rules are applied at boot. Reboot and check again. |
| The daemon is not running | `systemctl status nix.mount nix-daemon.service` | The daemon is bound to `nix.mount`. Check the mount and `/var/lib/nix`, then start `nix.mount`. |
| `/nix/store` is empty or missing | `systemctl status nix.mount` | The bind mount is not active. Start `nix.mount`, or reboot. |
| `/etc/nix` is missing | `ls /etc/nix` | The copy runs at boot. Reboot after the merge and check again. |
| `enable --now` exits non-zero after the download | The output shows `refresh_error` | Run `sudo systemd-sysext refresh` or reboot, then check `systemd-sysext status`. |

## What ships

| Item | What you get |
| --- | --- |
| Package | `nix-setup-systemd`, which brings the Nix binaries and the daemon units |
| Version | The image file name carries the `nix-setup-systemd` version, plus a `+rN` snosi revision when one is set |
| Image file | `nix_<version>_<os>_<arch>.raw.zst`; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/nix/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |
| Command | `/usr/bin/nix` |
| Services | `nix.mount`, `nix-daemon.socket`, and `nix-daemon.service`, enabled by `40-nix.preset` and started at boot by `10-nix.conf` |
| Mount | `/nix` is a bind mount of `/var/lib/nix` |
| Users and groups | `nix-users` with no members, and `nixbld` with `nixbld1` to `nixbld10` |
| Configuration | A default `/etc/nix`, held in `/usr/share/factory/etc` |
| State | `/var/lib/nix`: the store, profiles, and garbage-collection roots |

Each build checks that the Nix binary, the user rules, `nix-daemon.service`,
 `nix.mount`, and the boot drop-in are present. A build
that is missing one fails. The image is an overlay, so a later Base can break
an older Nix image.
