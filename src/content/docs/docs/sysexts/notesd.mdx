The notesd extension adds `notesd`, the Frostnotes notes daemon, to a Frostyard bootc image. It runs as lodge's Notes app, with the app id `notes`. A server that runs the suite's services runs [Floe](/docs/images/floe/). On a desktop, install the [Frostnotes Flatpak](/docs/apps/frostnotes/) instead. Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard bootc image built on Base.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/notesd/`.
- Free space in `/var` for the image.

notesd has no published test results on Frostyard images yet. Try it on a machine you can spare first.

You reach Notes in a browser through [lodge](/docs/sysexts/lodge/). Enable lodge first. The notesd extension declares no dependency on lodge, so enabling notesd does not enable lodge.

## Enable notesd

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=notesd
sudo updex features enable notesd --now
```

`notesd` appears as a component, with its feature disabled. The enable command
downloads the image, checks its checksum and signature, links it, and refreshes
the merge.

If `updex features list` does not show the feature, the image is older than the
extension. [Update the image](/docs/images/install-update/) first.

Start notesd:

Reboot. At boot the image merges the extensions, runs `systemd-sysusers` and
`systemd-tmpfiles --create`, reloads systemd, and `Upholds=` starts the units.

To start without a reboot:

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl start frostnotes-lodge.socket frostnotes.service
```

Without the first two commands, the socket fails on its group.

Check the merge and the units:

```bash
systemd-sysext status
systemctl status frostnotes-lodge.socket frostnotes.service
sudo -u frostnotes notesctl --socket /run/frostnotes/notesd.sock vault list
```

`systemd-sysext status` lists `notesd`, `systemctl status` shows both units
active, and `vault list` lists the vaults and prints no error.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the
download worked but the merge did not. Run `sudo systemd-sysext refresh`, or
reboot. Then run the checks above again.

## What runs

`frostnotes-lodge.socket` and `frostnotes.service` run on the host.

The drop-in `/usr/lib/systemd/system/multi-user.target.d/10-notesd.conf` has
`Upholds=` for both units, and the preset
`/usr/lib/systemd/system-preset/40-notesd.preset` enables both. Both start at
boot. If one stops, even with exit status 0, systemd starts it again. To stop it
for longer, remove the extension or mask the unit.

`extension-release.notesd` sets `EXTENSION_RELOAD_MANAGER=1`, so a merge or
refresh reloads systemd's unit files.

`frostnotes.service` runs `/usr/bin/notesd -lodge` as the system user
`frostnotes`, with its data in `/var/lib/frostnotes`. The vault work, which is
file watching, rescans, and version pruning, runs from boot, whether lodge runs
or not. `notesctl` reaches `notesd` on the private socket
`/run/frostnotes/notesd.sock`.

`frostnotes-lodge.socket` listens on `/run/lodge/apps/notes.sock` as owner
`frostnotes`, group `lodge`, mode `0660`. Only lodge's group can open it.

The sysusers file `/usr/lib/sysusers.d/frostnotes.conf` creates the user
`frostnotes`, the group `lodge`, and the group `lodge-apps`, with `frostnotes`
in `lodge-apps`. The user is never in group `lodge`. lodge's own extension is
not needed for the socket to start.

The lodge app files are in `/usr/share/lodge/apps/notes/`: `app.json` and
`web/`. The commands are `/usr/bin/notesd` and `/usr/bin/notesctl`.

## Update, roll back, and remove

Check for an update, then install it:

```bash
updex features check --component=notesd
sudo updex features update --component=notesd
```

By default, the update merges the new files at once, and systemd reloads its
unit files. The running daemon keeps its old binary until it restarts. New
users, groups, and directories wait for the next boot. A reboot applies
everything.

The new files wait for the next boot when you pass `--no-refresh`, when the
automatic update timer installs the update, or when the output says
`refresh skipped`: Updex skips the refresh when it cannot refresh safely. Then
reboot. See [Update](/docs/sysexts/manage/#update).

After a merged update, to switch now without a reboot:

```bash
sudo systemd-sysusers
sudo systemd-tmpfiles --create
sudo systemctl daemon-reload
sudo systemctl restart frostnotes-lodge.socket frostnotes.service
```

Roll back with `sudo updex features rollback notesd`. It takes effect at the
next boot. See [Roll back](/docs/sysexts/manage/#roll-back).

Remove notesd:

```bash
sudo updex features disable notesd --now --force
```

Updex unmerges all extensions on the host, deletes the image, and merges the
rest again. Reboot when the command finishes. Without `--force`, Updex refuses
while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package | `frostyard-notesd`, the `.deb` attached to the app's GitHub release, installed into the image with `dpkg`. The build checks the download against a pinned SHA-256, and checks that its dependencies are met before it installs. Its GitHub build-provenance attestation is checked when the pin is set and in every CI build, before the image is built |
| Feature | `Notes (Frostnotes notes daemon and Lodge notes app)` |
| Commands | `/usr/bin/notesd` and `/usr/bin/notesctl` |
| Service | `frostnotes.service`, which runs `/usr/bin/notesd -lodge` as the system user `frostnotes` |
| Socket | `frostnotes-lodge.socket` on `/run/lodge/apps/notes.sock`, owner `frostnotes`, group `lodge`, mode `0660` |
| Private socket | `/run/frostnotes/notesd.sock`, for `notesctl` |
| Data | `/var/lib/frostnotes` |
| User and group | `frostnotes`, group `lodge`, and `frostnotes` in group `lodge-apps`, from `/usr/lib/sysusers.d/frostnotes.conf` |
| Lodge app | `/usr/share/lodge/apps/notes/`, with `app.json` and `web/` |
| Activation | `/usr/lib/systemd/system/multi-user.target.d/10-notesd.conf` with `Upholds=`, and `/usr/lib/systemd/system-preset/40-notesd.preset` |
| Version | The image file name carries the `frostyard-notesd` package version, which is the app's release version |
| Image file | `notesd_<version>_13_x86-64.raw.zst`, where `13` is the OS version ID; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/notesd/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

<ExtensionSnapshot name="notesd" />

Each build checks the commands, the units, the sysusers file, the lodge app manifest and web page, and the preset, activation drop-in and extension-release files. A build that is missing one fails. Each build also checks that every upheld unit has no `Condition*=` line, or is a oneshot that stays active.
