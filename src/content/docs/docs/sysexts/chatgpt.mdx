The ChatGPT extension adds the ChatGPT desktop app, with Codex, to a Frostyard desktop image. Use it when you want the app on a desktop image. Every image carries the extension's definition, switched off. The extension itself is not in the image: Updex turns it on and downloads it.

## Before you start

You need:

- A Frostyard desktop bootc image: Snow, Snowfield, or Sundog, not Floe.
- Root access to enable, update, and remove the extension.
- Network access to `https://repository.frostyard.org/ext/chatgpt/`.
- Free space in `/var` for the download and the installed image.

The ChatGPT extension has no published test results on Frostyard images yet. Try it on a machine you can spare first.

## Enable ChatGPT

See what Updex found, then enable the feature and download it now:

```bash
updex features list --component=chatgpt
sudo updex features enable chatgpt --now
```

`chatgpt` appears as a component, with its feature disabled. The enable command downloads the image, checks its checksum and signature, links it, and refreshes the merge.

Check the merge and the files that the extension adds:

```bash
systemd-sysext status
command -v chatgpt
ls /usr/share/applications/chatgpt.desktop
```

`systemd-sysext status` lists `chatgpt`. `command -v` prints a path, and `ls` prints the launcher file.

If `enable --now` exits with a refresh error (`refresh_error` in JSON), the download worked but the merge did not. Run `sudo systemd-sysext refresh`, or reboot. Then run the checks above again.

## Use ChatGPT

Start ChatGPT from your applications, or run `chatgpt`. The command runs the app's `codex-launcher`. The extension ships no service and adds nothing to `/etc`.

## Update, roll back, and remove

See whether a newer image exists, then update:

```bash
updex features check --component=chatgpt
sudo updex features update --component=chatgpt
```

The update downloads the newest image and links it. A refresh replaces `/usr` under a running app, and a running app can fail. Close ChatGPT before you run `updex features update`, or update with `--no-refresh` and reboot. See [Manage system extensions](/docs/sysexts/manage/#update) for the check output and the update timer.

Roll back with `sudo updex features rollback chatgpt`. It takes effect at the next boot. See [Roll back](/docs/sysexts/manage/#roll-back).

Remove ChatGPT now:

```bash
sudo updex features disable chatgpt --now --force
```

Updex unmerges all extensions on the host, deletes the ChatGPT image, and merges the rest again. Your ChatGPT data stays in your home directory. Reboot when the command finishes. Without `--force`, Updex refuses while the image is merged.

## What ships

| Item | What you get |
| --- | --- |
| Package requests | `chatgpt` (from the OpenAI APT repository that the build uses) and `libglib2.0-bin` |
| Version | The image file name carries the `chatgpt` version, plus a `+rN` snosi revision when one is set |
| Command and launcher | `/usr/bin/chatgpt`, which points to `/usr/lib/chatgpt/codex-launcher`, and `/usr/share/applications/chatgpt.desktop` |
| Sandbox | No SUID `chrome-sandbox`. The app uses unprivileged user namespaces |
| Services | None |
| Image file | `chatgpt_<version>_<os>_<arch>.raw.zst`; `.raw.xz`, `.raw.gz`, and `.raw` also work |
| Download | From `https://repository.frostyard.org/ext/chatgpt/`, signature required (`Verify=true`), into `/var/lib/extensions.d/` |

Each build checks that these paths are present: the ChatGPT binary, `codex-launcher`, the `/usr/bin/chatgpt` link, the launcher, and the icon in `/usr/share/pixmaps`. A build that is missing one fails.
