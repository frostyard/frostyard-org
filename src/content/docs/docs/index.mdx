Frostyard makes bootc images and `/usr` system extensions, built with
[snosi](https://github.com/frostyard/snosi). These guides cover each Frostyard
image, every extension in the catalog, the apps, and the tools. Each page lists
its sources at the bottom.

:::caution[Support boundary]
Secure Boot, signed updates, and signed rollback are not production-ready yet.
Snow, Floe, and Sundog passed a fresh install in a virtual machine in lab
runs on 2026-10-24 and 2026-10-25. That is not a hardware test. See [Snow](/docs/images/snow/) and the snosi
[Bootc Secure Operations runbook](https://github.com/frostyard/snosi/blob/b2858ca0222814c395cf8248db98f3e096d57dc9/docs/bootc-secure-operations.md).
:::

## Install and first boot

Install with Firn. It needs UEFI, erases the disk you pick, and asks you
about each security choice. Start with
[Install a Frostyard image](/install): it covers checking the ISO, the disk
warning, first boot, and MOK enrollment.

Every image checks for updates hourly, stages a new version, and starts it at
your next normal reboot. It never forces a reboot.
[Install, update, and roll back](/docs/images/install-update/) takes you from
the download to a rollback.

Old nbc and native A/B installs got no new images or updates after
2026-09-30. They cannot convert in place: back up, install fresh, and restore.
See [Move from an nbc or A/B install](/docs/images/install-update/#move-from-an-nbc-or-ab-install).

## How a Frostyard system is built

A Frostyard system has three layers:

1. **The image.** It holds the read-only `/usr`, the kernel, the desktop or
   server software, and the updater.
2. **Your state.** `/var` holds homes, containers, and service data. `/etc`
   holds your configuration and carries it into each new version.
3. **System extensions.** EROFS images that add to `/usr` only. They cannot
   write `/etc` or `/var`. An extension keeps its default configuration in
   `/usr/share/factory/etc`, and `tmpfiles.d` copies it into `/etc` at boot.

Every image carries a definition for each extension in the catalog, switched
off. The extension itself is not in the image: you turn it on, and download
it, with [Updex](/docs/tools/updex/). Each extension page has the steps. An
enabled extension updates on its own: a new version is staged and starts at the next boot. See [Automatic updates](/docs/sysexts/manage/#automatic-updates).

Each extension page shows the newest version the catalog listed at its last
sync. Run `updex features check` to see what you can update to.
